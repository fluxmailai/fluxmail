title: 'Upgrade to 0.32.0'
description: 'Send empty values to clear draft fields, because update_draft now keeps the fields a call leaves out.'
updated: '2026-11-19'
---

Fluxmail 0.32.0 changes the `update_draft` MCP tool. Fields a call leaves out keep the draft's current values instead of being cleared.

## Find your migration

| Interface | Required changes |
| --- | --- |
| MCP | To clear a draft field with `update_draft`, send it empty. Calls that resend every field need no change. |
| CLI | None. `drafts update` still replaces the whole draft. |
| REST | None. `PUT /api/v1/accounts/{accountId}/drafts/{draftId}` still replaces the whole draft. |

## Clear draft fields explicitly

`update_draft` used to replace the whole draft, so leaving out `to`, `cc`, `bcc`, `subject`, the body or `attachments` removed them. It now keeps each field the call leaves out. A call that changes only the body, for example, keeps the draft's recipients, subject and attachments.

To remove something, send it empty:

| To remove | Send |
| --- | --- |
| To, Cc or Bcc recipients | `"to": []`, `"cc": []` or `"bcc": []` |
| The subject | `"subject": ""` |
| Every attachment | `"attachments": []` |

`bodyText` and `bodyHtml` belong to one body. Sending either replaces the whole body, so a call with only `bodyText` removes the HTML part. A list of `attachments` replaces all of the draft's attachments; to keep some, send them again with the new ones.

A reply draft keeps its recipients and subject when an update leaves them out, even when the call passes `replyToMessageId`. To take the recipients from the original message again, send `"to": []`. When you replace the body of a reply draft, pass `replyToMessageId` to keep the quoted original, as before.
