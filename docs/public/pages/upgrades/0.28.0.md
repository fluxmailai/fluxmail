description: 'Restart folder-filtered IMAP searches, check scheduled-draft permissions and back up the store.'

Fluxmail 0.28.0 changes IMAP page tokens for folder-filtered lists and searches, requires sending permission to change an active scheduled draft, and migrates the SQLite store to format 9.

## Find your migration

| Interface | Required changes |
| --- | --- |
| MCP | Omit `pageToken` when restarting an affected IMAP list or search, including each affected account in a batch search. `update_draft` and `delete_draft` require `mail.send` for an active scheduled draft. |
| CLI | Omit `--page-token` when restarting an affected IMAP list or search. `drafts update` and `drafts delete` require `mail.send` for an active scheduled draft. |
| REST | Omit `pageToken` when restarting an affected IMAP list or search, including each affected account in a batch search. Draft update and deletion requests require `mail.send` for an active scheduled draft. |

## Restart affected searches

Discard saved page tokens from IMAP lists and searches that used a folder filter, including a folder role such as `inbox`. Restart the same request without a page token, then use the new response's `nextPageToken` to continue. Older tokens return `invalid_request`.

Gmail, Outlook and IMAP searches without a folder filter need no token migration.

## Check scheduled-draft permissions

A connection without `mail.send` now receives `permission_denied` if it edits or deletes a draft with a pending or sending schedule. This applies to MCP, CLI and REST. A draft edit changes the message that will go out, so `mail.drafts` alone no longer permits it.

Have an authorized sender cancel a pending schedule before a connection without `mail.send` changes its draft. If the schedule is already sending, it cannot be canceled; wait for delivery to finish and check the result. An edit cannot change a message that has already gone out.

If the connection should control outgoing mail, grant `mail.send` in addition to its existing draft permissions. For a local stdio client, add `--allow mail.send` to its permission options. For an API key, update its permissions as described in [Permissions](/docs/permissions). For an OAuth MCP connection, run `fluxmail connections revoke <connection-id>`, connect the client again, and approve sending permission on the sign-in page.

Connections that already have `mail.send` can keep editing scheduled drafts. Clients that do not change active scheduled drafts need no permission migration.

## Back up the store

Stop every process sharing the data directory before the first 0.28.0 process opens it. Fluxmail backs up the store before migrating it to format 9. Keep a [complete pre-upgrade backup](/docs/backup-and-restore), including the encryption key, because Fluxmail 0.27.0 cannot open a format 9 store. Rolling back requires restoring that backup.
